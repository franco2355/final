Arquitectura de navegacion del cuatri

Pensalo como dos mundos que se unen al final. Un mundo "piensa" y decide a donde ir (sensores + localizacion + Nav2 + UI), y el otro mundo "mueve" el robot real (controller_server + serial + ESP32).

Entrada real: ./tools/launch_real_nav.sh
Actuacion real: ./tools/launch_controller.sh
UI manual: web_zone_server en 8766
Salida final al robot: /cmd_vel_final

1. Stack general

Esta es la pelicula completa desde los sensores hasta las ruedas.

Sensores

Pixhawk + RS16

Publican /gps/fix, /imu/data, /odom y /scan_3d.

→
Localizacion

EKF + navsat_transform

Fusionan GPS, IMU y odometria. Salen /odometry/local, /odometry/gps y los frames map → odom → base_footprint.

→
Navegacion

Nav2

Planifica y controla. Genera la velocidad automatica que despues pasa por seguridad.

Seguridad

collision_monitor

Toma /cmd_vel_nav y saca /cmd_vel_safe, frenando si ve obstaculos con LiDAR o ultrasounds.

→
Arbitraje

nav_command_server

Decide si manda automatico o manual. Convierte todo a interfaces/CmdVelFinal y publica /cmd_vel_final.

→
Actuacion

controller_server

Toma /cmd_vel_final, lo transforma a direccion/freno/marcha y lo manda por serial al ESP32.

→
Hardware

ESP32 + actuadores

Mueven realmente direccion, traccion y freno del cuatri.

2. Flujo automatico

Asi funciona cuando le mandas waypoints o una ruta desde la web.

UI

Pagina web

Mandas waypoints en lat/lon por WebSocket.

→
Gateway

web_zone_server

Recibe los mensajes de la web y llama servicios ROS.

→
Servicio

set_goal_ll

Llega al nav_command_server como SetNavGoalLL.

→
Conversion

fromLL

Convierte lat/lon a posiciones del frame map.

→
Nav2

Actions

Ejecuta FollowWaypoints o NavigateThroughPoses.

En automatico, Nav2 produce velocidad; collision_monitor la filtra; nav_command_server la convierte a /cmd_vel_final.
El ultimo tramo siempre es el mismo: /cmd_vel_final → controller_server → serial → ESP32.

3. Flujo manual desde la pagina o joystick

La forma correcta de meter manual es imitar la pagina, no saltarse el backend.

Operador

WASD / joystick

El usuario genera avance, giro y freno.

→
WebSocket

set_manual_mode + set_manual_cmd

La pagina habla con web_zone_server en el puerto 8766.

→
ROS

/cmd_vel_teleop

El gateway publica el comando manual en el topic de teleop.

→
Arbitraje

nav_command_server

Toma control manual, cancela autonomia si hace falta y vuelve a publicar /cmd_vel_final.

→
Actuacion

controller_server

Manda el comando fisico al cuatri.

Launches que importan

./tools/launch_real_nav.sh Levanta sensores, EKF, navsat_transform, Nav2, zonas, snapshot y el backend web. En la practica, es el "cerebro" del stack.
./tools/launch_controller.sh Levanta controller_server. Sin esto, el stack puede pensar y mostrar estado, pero no llega al ESP32.

Topicos y servicios clave

/gps/fix GPS crudo desde Pixhawk.
/imu/data IMU usada por robot_localization.
/odometry/local Odometria filtrada local del EKF.
/scan LaserScan derivado del LiDAR 3D para costmaps.
/cmd_vel_safe Velocidad ya pasada por seguridad.
/cmd_vel_teleop Entrada manual desde la web o joystick.
/cmd_vel_final Salida unica hacia el controlador fisico.
/nav_command_server/set_goal_ll Servicio para mandarle waypoints geograficos.

Frase corta para entenderlo

Automatico: sensores ubican al robot, Nav2 decide a donde ir, seguridad filtra, y controller_server mueve el cuatri.
Manual: la pagina o el joystick no mueven directo; le piden al backend manual que tome control, y el backend vuelve a usar el mismo tramo final.
Salida final real: casi todo el sistema existe para terminar produciendo /cmd_vel_final.

Ojo: cosas corridas en el repo

real.launch.py parece incompleto

En simulacion el repo si agrega nav_command_server, pero en el real.launch.py de fuente no aparece agregado. La arquitectura lo necesita.

Drift en /cmd_vel_teleop

joystick_node.py publica geometry_msgs/Twist, pero nav_command_server hoy consume interfaces/CmdVelFinal. Eso explica por que el teleop clasico esta raro.

Conflicto sin resolver en localizacion

dual_ekf_navsat_params.yaml todavia tiene marcadores de merge en el datum. Eso es ruido real del repo fuente.
